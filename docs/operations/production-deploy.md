# Production deployment

How Journal Watch is deployed today, and how to change it safely. This page
describes the layout and the standard procedures; the exact commands for
restores, rollbacks and the hurdles we have hit are in
[deploy-runbook.md](deploy-runbook.md).

These pages are built into the production image and served by the app at
`/editorial/docs/` (the operations section requires a chief editor or
regional coordinator login; the user guide is public).

---

## Where things live

| Thing | Location |
|-------|----------|
| Production host | SSH alias `journal-watch-vps` (defined in `~/.ssh/config`) |
| Server repo (canonical runtime config) | `github.com/uppertoe/journal-watch-vps`, cloned at `/opt/deploy` on the host and at `~/Documents/developer/journal-watch-vps` locally |
| Docker Compose project root | `/opt/deploy` (always run `docker compose` from here) |
| Server-level env | `/opt/deploy/.env` — `DOMAIN` (and optional `ACME_EMAIL`), read by Caddy |
| App env | `/opt/deploy/apps/journal-watch/.env` — every Django, Celery, Planka and AWS variable |
| App compose file | `/opt/deploy/apps/journal-watch/docker-compose.yml` (pulled in by the root `docker-compose.yml` `include:` list) |
| Caddy routes for the app | `/opt/deploy/apps/journal-watch/journalwatch.caddy`, rendered into the committed bundle `.generated/caddy/apps.caddy` |
| Deploy helper | `~/deploy` on the host (managed by the scaffold's Ansible `deploy-user` role) |
| Backup config | Server repo `backup/config.env` and `backup/services/*.env`, deployed by Ansible to `/etc/restic/` on the host |
| Application images | Docker Hub `uppertoe/journalwatch-app` and `uppertoe/journalwatch-mjml`, built by GitHub Actions from this repo |

The server repo follows the hardened-Caddy scaffold
(`vps-base-template`, vendored as the `scaffold/` git submodule). The scaffold
owns the Caddy base service, the Ansible hardening roles and the backup
tooling; the server repo owns `apps/journal-watch/`.

> The files under `deploy/journalwatch/` in this application repo are a
> **synced copy** of `apps/journal-watch/` (last synced 2026-09-05). The
> server repo remains the runtime source of truth: make the change there,
> then copy it back so the two stay identical.

## What runs on the host

All services are defined in `apps/journal-watch/docker-compose.yml`. Compose
service names (not container names) are what you use with
`docker compose exec`, `logs` and `up -d`.

| Service | Image | Role |
|---------|-------|------|
| `caddy` (+ one-shot `caddy-init`) | `caddy:2-alpine` (digest-pinned by the scaffold) | TLS termination, static files, `/media/*` proxy to S3, reverse proxy. Runs as uid 65531. |
| `journal-watch` | `${JW_DOCKERHUB_NAMESPACE}/journalwatch-app:${JW_APP_TAG:-latest}` | Django under gunicorn on port 5000. Caddy reaches it as `journal-watch:5000`. |
| `jw_celeryworker` | same image | Celery worker with the beat scheduler embedded (`celery ... worker --beat --concurrency=1 --max-tasks-per-child=100`). There is no separate beat service. |
| `jw_postgres` | `postgres:17-alpine` | Django database. Bound to `127.0.0.1:5432` on the host for the backup agent. `pg_stat_statements` enabled. |
| `jw_redis` | `redis:7-alpine` | Celery broker and Django cache/sessions. |
| `jw_mjml` | `${JW_DOCKERHUB_NAMESPACE}/journalwatch-mjml:${JW_APP_TAG:-latest}` | MJML TCP renderer for newsletter email. |
| `jw_planka` | `ghcr.io/plankanban/planka:2.1.0@sha256:32c919d9…` | Kanban board, served at `planka.<domain>`. |
| `jw_planka_postgres` | `postgres:16-alpine` | Planka's own database. Bound to `127.0.0.1:5433`. |
| `jw_flower` | same as app image | **Not deployed.** Sits behind the `flower` compose profile, which is not enabled, and `flower.<domain>` has no DNS record or Caddy site block. |

Networks: `journal-watch_proxy` (generated by the scaffold; only Caddy,
`journal-watch` and `jw_planka` join it) and `jw_internal` (the app's private
backend network).

Named volumes: `jw_postgres_data`, `jw_postgres_backups`, `jw_planka_data`,
`jw_planka_postgres_data`, `jw_access_logs`, `jw_staticfiles`.

### How requests are served

- `www.<domain>` redirects to the apex.
- `/static/*` is served by Caddy from the `jw_staticfiles` volume (populated
  by `collectstatic` during deploy), with long-lived immutable cache headers
  for fingerprinted files and precompressed `br`/`gzip` variants.
- `/media/*` is reverse-proxied by Caddy to the S3 media bucket so images are
  same-origin. This requires `DJANGO_AWS_S3_CUSTOM_DOMAIN` in the app env to be
  the site domain.
- Everything else goes to `journal-watch:5000`. TLS is terminated at Caddy, so
  `DJANGO_SECURE_SSL_REDIRECT=False` in the app env.
- `planka.<domain>` proxies to `jw_planka:1337`; the login cover image is
  served by Caddy from `apps/journal-watch/planka/`, mounted at `/srv/planka`.

### Authentication for Planka

Django is the OIDC provider (django-oauth-toolkit, mounted at `/o/`). Planka
is registered as a client by `manage.py setup_planka_oidc`. There is no
separate identity provider in the stack.

**Planka is pinned by digest to `2.1.0@sha256:32c919d9…` because newer
releases break the OIDC login flow. Do not bump it without re-testing SSO end
to end.**

## Routine deploy (application release)

No build happens on the server and no manual `migrate` or `collectstatic` is
needed.

1. Merge or push to `main` in this repo. The GitHub Actions workflow
   `.github/workflows/dockerhub-images.yml` first runs ruff and the full
   test suite; only when they pass does it build `uppertoe/journalwatch-app`
   and push it tagged `latest` and `sha-<7-char commit>`. The MJML image is rebuilt only when
   `compose/production/mjml-tcp/**` changes, on a `v*` tag, or on a manual
   `workflow_dispatch`. A `v*` tag produces `<version>` tags instead of
   `latest`.
2. Wait for the workflow to finish (about two minutes):

   ```bash
   gh run list --workflow dockerhub-images.yml --limit 1
   gh run watch <run-id>
   ```

3. Deploy:

   ```bash
   ssh journal-watch-vps ./deploy
   ```

`~/deploy` does, in order:

- `git pull --recurse-submodules` in `/opt/deploy`
- `docker compose pull --policy always`
- locks every `.env` in the checkout to mode 600 and makes everything else
  containers read (`apps/`, `scaffold/`, `.generated/`, `Caddyfile`)
  world-readable, because Caddy runs as uid 65531
- runs each executable `apps/*/deploy.sh` hook. The Journal Watch hook starts
  `jw_postgres`, then runs `python manage.py migrate --noinput` and
  `python manage.py collectstatic --noinput` in a throw-away `journal-watch`
  container
- `docker compose up -d --remove-orphans --wait --force-recreate`
- `docker image prune -af` once the new containers report healthy

Verify afterwards:

```bash
ssh journal-watch-vps 'cd /opt/deploy && docker compose ps'
curl -sS -o /dev/null -w '%{http_code}\n' https://journalwatch.org.au/healthz
```

Because Compose loads the app file through `include:`, variable
interpolation for `apps/journal-watch/docker-compose.yml` is resolved from
`apps/journal-watch/.env` automatically. You do not need to
`source` the env file before running `docker compose` from `/opt/deploy`.

## Changing configuration

### Environment variables

1. Edit `/opt/deploy/apps/journal-watch/.env` (or `/opt/deploy/.env` for
   `DOMAIN` / `ACME_EMAIL`).
2. Recreate the affected services:

   ```bash
   cd /opt/deploy
   docker compose up -d journal-watch jw_celeryworker   # or jw_planka, etc.
   ```

3. Confirm the container sees the new value:

   ```bash
   docker compose exec -T journal-watch env | grep DJANGO_AWS_S3_CUSTOM_DOMAIN
   ```

**Never use `docker compose restart` after editing an env file.** `restart`
reuses the container's original environment and silently ignores the edit.

### Caddy routes or the compose include list

1. Edit `apps/journal-watch/journalwatch.caddy` (or the `include:` list in the
   root `docker-compose.yml`) in your local clone of the server repo. Keep
   comments in `.caddy` files free of curly braces — the renderer counts them
   to find block boundaries.
2. Re-render and commit the generated bundle:

   ```bash
   bash scaffold/docker/render-caddy-routes.sh
   git add .generated apps docker-compose.yml
   git commit
   git push
   ```

3. `ssh journal-watch-vps ./deploy`.

Do not add a site block for a hostname that has no DNS record: Caddy will
retry the ACME challenge for it every few minutes (this is why the Flower
block was removed).

### Compose changes (limits, commands, images)

Edit `apps/journal-watch/docker-compose.yml` locally, commit, push, then
`./deploy`. The web-facing service must stay named `journal-watch` (the
scaffold derives the proxy network from the directory name and fails the
render otherwise). Any change that removes or renames a service should be
followed by `docker compose ps` to confirm nothing is orphaned.

### Pinning or rolling back the app image

The app image tag comes from `JW_APP_TAG` in the app env (default `latest`).
To run a specific build, set `JW_APP_TAG=sha-<7-char commit>` and run
`./deploy`; set it back to `latest` (or remove it) to resume tracking `main`.

## Scaffold updates (host-level controls)

The server repo has two update lanes:

| Lane | What flows | How it is applied |
|------|------------|-------------------|
| Compose / Caddy | app images, routes, Caddy base | `./deploy` |
| Ansible | hardening roles, timers, the `~/deploy` helper itself | bump the `scaffold/` submodule, read `scaffold/UPGRADING.md`, re-run `site-quick.yml` |

To bump the scaffold:

```bash
cd ~/Documents/developer/journal-watch-vps
git -C scaffold fetch origin
git -C scaffold log --oneline HEAD..origin/main      # what is pending
# read scaffold/UPGRADING.md for every entry after: git -C scaffold log -1 --format=%cs
git -C scaffold checkout origin/main
bash scaffold/docker/render-caddy-routes.sh          # the Caddy base may have changed
git add scaffold .generated && git commit -m "chore: bump scaffold" && git push
ssh journal-watch-vps ./deploy
ANSIBLE_CONFIG=scaffold/ansible/ansible.cfg ansible-playbook -i ansible/hosts scaffold/ansible/site-quick.yml
```

**Outstanding as of 2026-09-04:** the compose/Caddy lane was migrated to
scaffold `0c42cb1` on 2026-09-02, but `site-quick.yml` has not been re-run
since. Host-level controls (timers, AIDE, egress firewall, the managed
`~/deploy`) are still at the older scaffold. The play will stop with a
`fail:` until the inventory has the values the newer scaffold requires
(`notify_deadman_url` / `notify_ntfy_url`, or the explicit
`*_accept_none: true` opt-outs). Decide those, then run the play.

## First-time provisioning

This is the path for a fresh VPS. It has been walked once, on the current
host; re-read `scaffold/docs/03-provisioning-a-server.md` and
`scaffold/docs/09-recovery.md` in the server repo before doing it again.

### 1. Provision the host (local machine)

```bash
cd ~/Documents/developer/journal-watch-vps
# ~/.ssh/config needs a Host entry named journal-watch-vps
cp ansible/hosts.example ansible/hosts && $EDITOR ansible/hosts   # IP, key path
ansible-galaxy collection install -r scaffold/ansible/requirements.yml
export ANSIBLE_CONFIG=scaffold/ansible/ansible.cfg
ansible-playbook -i ansible/hosts scaffold/ansible/bootstrap.yml --ask-pass   # once, as root
ansible-playbook -i ansible/hosts scaffold/ansible/site-first-run.yml
ansible-playbook -i ansible/hosts scaffold/ansible/site-quick.yml
bash scripts/post-provision-smoke-test.sh journal-watch-vps
```

### 2. Clone the server repo and create the env files (on the host)

```bash
git clone --recurse-submodules git@github.com:uppertoe/journal-watch-vps.git /opt/deploy
cd /opt/deploy
cp .env.example .env && $EDITOR .env                       # DOMAIN=journalwatch.org.au
cp apps/journal-watch/.env.example apps/journal-watch/.env
python3 scripts/generate_journal_watch_env.py               # fills empty secret values only
$EDITOR apps/journal-watch/.env                             # domain, email, AWS placeholders
chmod 600 .env apps/journal-watch/.env
```

`generate_journal_watch_env.py` fills `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`,
`WEBHOOK_SECRET`, `CELERY_FLOWER_PASSWORD`, `SECRET_KEY`,
`PLANKA_POSTGRES_PASSWORD`, `OIDC_CLIENT_SECRET`, `DEFAULT_ADMIN_PASSWORD`
and `PLANKA_WEBHOOK_SECRET` when they are blank, and leaves everything else
alone. Two values need attention by hand:

- `OIDC_RSA_PRIVATE_KEY` — `openssl genrsa 4096 | base64 -w 0`
- `WEBHOOK_SECRET` — Anymail's SES webhook uses HTTP basic auth, so this must
  be in `username:password` form. Use the same value in the SNS subscription
  URL (see below).

### 3. Provision AWS (local machine)

Follow [aws-setup.md](aws-setup.md). Paste the printed `jw-django` and
`jw-planka` keys into `apps/journal-watch/.env`, and the `jw-backup` keys
into the server repo's `backup/config.env`.

### 4. DNS

| Type | Name | Value |
|------|------|-------|
| A | `journalwatch.org.au` | VPS IP |
| A | `www.journalwatch.org.au` | VPS IP |
| A | `planka.journalwatch.org.au` | VPS IP |

Plus the SES records printed by `aws_setup.py`, then DMARC and BIMI once SES
is verified (see "Email authentication DNS" below).

### 5. First deploy and application bootstrap

```bash
ssh journal-watch-vps ./deploy          # caddy-init, migrate, collectstatic, up
ssh journal-watch-vps
cd /opt/deploy
docker compose exec -T journal-watch python manage.py create_chief_editor you@example.com --name "Your Name"
docker compose exec -T journal-watch python manage.py setup_planka_oidc
```

Then set up the Planka API key: log in at `https://<domain>/editorial/settings`
as the chief editor and use **Run setup_planka_api_key**, or run
`docker compose exec -T journal-watch python manage.py setup_planka_api_key`.
Afterwards:

1. Uncomment `OIDC_ENFORCED=true` in `apps/journal-watch/.env`.
2. `docker compose up -d jw_planka`.
3. Remove `DEFAULT_ADMIN_PASSWORD` from the env file — it is no longer used.

From this point Planka login is SSO-only through Django.

### 6. Subscribe SNS to the Django webhook

Once the site is reachable over HTTPS, run the `aws sns subscribe` command
that `aws_setup.py` printed. Django auto-confirms; the subscription should
show **Confirmed** in the SNS console within seconds.

### 7. Backups

Backups are owned by the server repo, not this one. In your local clone of
the server repo:

```bash
cp backup/config.env.example backup/config.env && $EDITOR backup/config.env          # jw-backup keys, SMTP for alerts
# backup/services/journal-watch.env and backup/services/planka.env already exist; check them
ansible-playbook -i ansible/hosts ansible/backup.yml
bash scripts/post-provision-smoke-test.sh journal-watch-vps --require-backup
ssh journal-watch-vps sudo systemctl start backup.service
ssh journal-watch-vps journalctl -u backup.service -f
```

The role installs restic, `/opt/backup/{backup,restore,restore-drill}.sh`,
`/etc/restic/config.env`, `/etc/restic/services/*.env`, and the
`backup.timer` (hourly), `backup-verify.timer` (weekly, Sunday 03:17 UTC on
this host) and `restore-drill.timer` (monthly) units.

### 8. Email authentication DNS

After `aws_setup.py` has printed the SES records and the identity shows as
verified, add DMARC, then BIMI.

**DMARC** (required by Gmail for bulk senders). Start at `p=none` until SPF
and DKIM are both passing, then move to `p=quarantine`:

| Type | Name | Value |
|------|------|-------|
| TXT | `_dmarc.journalwatch.org.au` | `v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@journalwatch.org.au; pct=100` |

**BIMI** shows the newsstand icon next to newsletters in Gmail, Apple Mail,
Yahoo and Fastmail. It requires DMARC at `p=quarantine` or `p=reject`. The
SVG (SVG Tiny PS format) ships in this repo at
`spanza_journal_watch/static/images/logo/newsstand-icon-bimi.svg` and is
served by Caddy after `collectstatic`:

| Type | Name | Value |
|------|------|-------|
| TXT | `default._bimi.journalwatch.org.au` | `v=BIMI1; l=https://journalwatch.org.au/static/images/logo/newsstand-icon-bimi.svg;` |

Check with `dig TXT _dmarc.journalwatch.org.au`,
`dig TXT default._bimi.journalwatch.org.au`, and
`python manage.py check_email_auth` inside the app container. A Verified
Mark Certificate is not required for the logo to display.

## Verification checklist

After a deploy or any structural change:

- [ ] `docker compose ps` from `/opt/deploy` — every service `running` or `healthy`; no orphans
- [ ] `https://journalwatch.org.au/healthz` returns 200
- [ ] `https://journalwatch.org.au/` and `/editorial/` load
- [ ] `https://planka.journalwatch.org.au/` redirects to Django login and SSO completes
- [ ] a hashed asset under `/static/` returns `Cache-Control: public, max-age=31536000, immutable`
- [ ] an image under `/media/` returns 200 from the site domain
- [ ] `docker compose logs --tail=100 journal-watch jw_celeryworker` show no tracebacks
- [ ] `ssh journal-watch-vps systemctl list-timers backup.timer backup-verify.timer` — timers present and scheduled
- [ ] after env changes: `docker compose exec -T journal-watch env | grep <VAR>` shows the new value
